# 每日精选 · 2026-04-14

> **上下文工程：从提示工程到注意力预算管理**
> 来源：**Anthropic** · [面向 AI 智能体的高效上下文工程](../anthropic/context-engineering)
> **一句话：** Anthropic 官方把「上下文工程」定义为提示工程的进化形态，核心是把有限的注意力预算花在信号密度最高的地方。

## 速览

这篇博客把「Context Engineering」从行业热词升格为 Anthropic 官方方法论，主张三条：

1. **从提示工程到上下文工程**——长任务跨多轮、多工具、多阶段，决定表现的是 **每一轮推理时可见的全部信息**，而不只是那条 system prompt。
2. **上下文腐化与注意力预算**——模型在长上下文中的表现会随无关信息增加而衰减；工程师要做的，是把「注意力预算」当成稀缺资源来分配。
3. **架构层面的根源**——当前 Transformer 的注意力机制结构性地导致「上下文腐化」，这决定了上下文工程不是 prompt 微调，而是 **系统级设计**。

文章给了系统提示结构、动态上下文拼接、压缩 vs 蒸馏等实操指南。

## 🔑 核心洞察

- **「注意力预算」** 是这篇最关键的一词——它把 prompt 从玄学变成 **可量化的资源分配问题**。
- 和《Writing Tools for Agents》是同一批人写的——Anthropic 正在连发一整套 **面向长任务 Agent 的工程方法论**。
- 这会倒逼整个 agent 生态重写评估标准：不再只看单轮准确率，而要看 **「上下文衰减后的鲁棒性」**。

## 一句话推荐

做 agent / RAG / 长工作流的工程师今年必读。
