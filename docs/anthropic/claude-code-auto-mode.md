# Claude Code Auto Mode：让 AI 自主决定权限的安全实验

> **原标题：** Claude Code Auto Mode
> **发布日期：** 2026年3月24日
> **原文链接：** https://www.anthropic.com/news/claude-code-auto-mode

---

## 一句话摘要

Anthropic 为 Claude Code 推出 Auto Mode（研究预览），让 AI 自主决定哪些操作安全可执行、哪些需要人类审批，通过 AI 分类器在"完全人工审批"与"跳过所有权限"之间找到平衡点。

---

## 完整核心内容翻译

### 背景与动机

Claude Code 此前的权限模型存在两个极端：要么开发者逐一审批每个文件写入和 bash 命令（效率低下），要么使用 `dangerously-skip-permissions` 跳过所有审批（风险过高）。Auto Mode 旨在消除这一非此即彼的选择。

### 核心机制

Auto Mode 在每次工具调用执行前，由一个 AI 分类器（classifier）审查该操作：

- **意图一致性检查：** 评估拟议操作是否与用户的原始意图一致
- **提示注入检测：** 识别处理内容中可能隐藏的恶意指令
- **风险评估：** 对潜在破坏性操作（如批量删除文件、敏感数据外泄、恶意代码执行）进行拦截

### 支持范围

当前 Auto Mode 仅支持：
- **Claude Sonnet 4.6**
- **Claude Opus 4.6**

面向 Enterprise 和 API 用户逐步推出。

### 安全建议

Anthropic 明确建议在**隔离环境（sandboxed environments）**中使用 Auto Mode，远离生产系统。公司也坦承分类器存在局限性——当用户意图模糊或 Claude 对环境上下文不足时，仍可能放行部分风险操作。

### 与现有方案的对比

```
完全手动审批 ←——→ Auto Mode ←——→ dangerously-skip-permissions
（最安全/最慢）    （平衡点）        （最快/最危险）
```

---

## 技术要点

1. **AI 分类器前置审查：** 每个工具调用在执行前都经过独立的 AI 分类器审查，形成"双模型架构"——一个模型生成操作，另一个模型审查操作的安全性。
2. **提示注入防御：** 分类器专门检测处理内容中的隐藏指令，这对于处理不可信来源代码的智能体尤为关键。
3. **渐进式权限模型：** Auto Mode 不是二元的"全允许/全拒绝"，而是根据操作类型和上下文动态决策。
4. **透明度局限：** Anthropic 未公开分类器的具体判断标准，开发者无法预测哪些操作会被放行或拦截。
5. **环境隔离推荐：** 官方建议在沙箱中使用，说明 Anthropic 自身也认为当前分类器的可靠性尚不足以用于生产环境。

## 深度解读

### 🟢 通俗版（非专业读者）

想象你请了一个非常能干的助手帮你整理办公室。以前你有两个选择：要么他每搬一个东西都问你"这个可以动吗？"（效率极低），要么你说"随便搬"（可能他把重要文件扔了）。Auto Mode 就像给这个助手配了一个"安全顾问"——助手想做什么之前，安全顾问先评估一下"这个操作有没有风险"。大部分日常操作会自动放行，只有可疑的操作才会暂停等你确认。

**为什么重要：** 这是 AI 编程助手从"工具"向"自主智能体"演进的关键一步。如果安全问题解决不了，AI 就永远只能是需要人盯着的工具。

### 🔴 深入版（有算法基础的读者）

Auto Mode 的核心创新在于引入了**运行时安全分类器**作为智能体动作的"守门人"。这种"生成器-审查器"双模型架构与 Constitutional AI 的思路一脉相承——用 AI 来监督 AI。

关键技术挑战：
- **分类器的精度-召回权衡：** 过于保守会频繁中断工作流（退化为手动模式），过于宽松则失去安全保障。Anthropic 选择偏保守但未公布具体阈值。
- **上下文窗口限制：** 分类器需要理解用户意图、当前操作、以及环境上下文才能做出准确判断，但长会话中意图可能发生漂移。
- **对抗性鲁棒性：** 如果攻击者了解分类器的判断逻辑，可能构造绕过检测的提示注入。Anthropic 未公开分类器细节，部分原因可能是安全考量。

与 OpenAI Codex 的沙箱方案对比：OpenAI 选择在云端完全隔离的沙箱中运行代码，从架构层面消除风险；Anthropic 选择在本地环境运行但通过 AI 分类器过滤风险。前者更安全但灵活性受限，后者更灵活但依赖分类器的可靠性。

---

## 延伸思考

1. **AI 监督 AI 的递归问题：** 如果分类器本身可以被欺骗，那么谁来监督分类器？是否需要多层级的安全审查链？
2. **开发者信任校准：** Auto Mode 可能导致开发者对 AI 操作的"警惕度衰减"——习惯了自动放行后，可能忽视偶尔弹出的审批请求。
3. **从编程到通用智能体：** 如果这种"AI 分类器守门"模式被证明有效，是否会推广到所有智能体场景（如文件管理、邮件发送、财务操作）？
